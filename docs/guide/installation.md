# Installation

## Requirements

| Requirement | Version |
|---|---|
| Docker | 24+ |
| Docker Compose | v2.20+ (plugin) |
| Ring account | any — a subscription is **not** required |
| CPU | x86-64 or arm64 (e.g. Raspberry Pi 4/5) |

Any machine that stays on works: a home server, a NAS with Docker, or a Raspberry Pi.

## Quick start

### 1. Clone the repository

```bash
git clone https://github.com/m4rcelnoel/ring-off.git
cd ring-off
```

### 2. Start the stack

```bash
docker compose up -d
```

::: tip No config files to copy
`config/go2rtc.yaml` is created automatically on first start, and cameras are added to it as they are discovered. There is no `.env` to fill in — the RTSP credentials for ring-mqtt's internal stream server are generated by ring-mqtt itself and picked up automatically.
:::

### 3. Open the web UI

Go to **`http://<your-server-ip>:8080`** and follow the setup wizard.

## The setup wizard

1. **Checks** — confirms the broker, ring-mqtt, go2rtc and the data folders are healthy, and tells you exactly what to fix if one is not.
2. **Ring** — your email and password, plus a 2FA code if your account uses one.
3. **Devices** — cameras and chimes appear as ring-mqtt announces them.
4. **Cameras** — name each one ("Front Door" rather than `Camera 169F41`) and switch off any you don't want.
5. **Alerts** — optional clip recording and push notifications, with a button that sends a test and reports what actually happened.
6. **Finish** — optionally set a dashboard password.

The Ring refresh token is saved to `data/ring-mqtt/ring-state.json`, and ring-mqtt is restarted within a few seconds to load it. You only need to sign in once; the token survives restarts.

Afterwards, **Settings → Cameras** lets you rename or hide a camera at any time. **Run setup again** in the same panel replays the whole wizard, e.g. to sign in to a different Ring account.

::: details ring-mqtt's own token UI (port 55123)
ring-mqtt has its own token setup page on port 55123. You don't need it, and it isn't published because it has no authentication. As a fallback if the in-app sign-in fails, publish it temporarily in `docker-compose.override.yml` and remove it again afterwards:

```yaml
services:
  ring-mqtt:
    ports: ["55123:55123"]
```
:::

## Optional services

`go2rtc` (live streaming) and `recorder` (clip recording) are included by default. To switch one off without editing `docker-compose.yml`, give it an inactive profile in `docker-compose.override.yml`:

```yaml
services:
  recorder:
    profiles: ["disabled"]
```

## Local changes belong in the override file

Never edit `docker-compose.yml` itself — it is replaced on every update. Put NAS paths, extra ports and environment variables into `docker-compose.override.yml`, which Compose loads automatically and git ignores:

```bash
cp docker-compose.override.yml.example docker-compose.override.yml
```

The example file contains ready-to-uncomment snippets for the common cases. See [Updating](/guide/updating) for why this matters.
